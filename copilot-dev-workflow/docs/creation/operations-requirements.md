# 運用機能の要件 v0.6.0

REQ-OPS-01 doctor: Python/Git/CLI版・21担当・明示モデル・個人上書き・実ホスト観測・資料接続・一時領域書込を診断。未確認を成功としない。
REQ-OPS-02 live-eval: 使い捨てサンプルGit案件、一問一答/設計差戻し/実装/UT/結合/中断再開の試験シナリオ、実ホスト呼出しとログ・終了・対象ハッシュ・観測モデルの保存。生成結果は独立評価し、未実行をPASSにしない。
REQ-OPS-03 hooks: ネイティブ入出力形式の事前フック、レビュー書込/未承認実装/マージ等の禁止、既存gate確認へ接続。フックは完全なセキュリティ境界ではない。CI併用。設定は可変領域で明示設定。
REQ-OPS-04 update: 導入ベースのハッシュ/版、3者比較、ローカル変更保持、競合時無変更、バックアップ/復元、旧版導入の基準登録。dry-run既定。
REQ-OPS-05 sources: URL/取得/更新日時/ハッシュ/保存先を固定。再取得観測を比較し、期限切れ・欠落・変更時停止。impactへ接続。Notion接続そのものは既存MCPに依存。
REQ-OPS-06 dashboard: 現在工程/停止理由/次操作/指摘/見積対実績をHTMLへ生成。HTMLエスケープ、閲覧で副作用なし。正本MDは既存ファイルを更新。
REQ-OPS-07 quality: 基準Gitコミットと品質設定/テストファイル群を比較。追加・削除・変更を検出。変更理由と人の承認原文にハッシュで結びつける。CI側で信頼基準を指定し、自動承認しない。

AC-OPS-01 全機能は両版同じ契約。製品別モデル・パス・hookだけ差分。
AC-OPS-02 正常/拒否/競合/再実行/注入対策を検証し、追加Pythonも行/分岐100%。
AC-OPS-03 実AI認証なし時は未検証を明記。実機試験は導入先で再現可能。
AC-OPS-04 各工程MDは/tmpの同一案件ディレクトリで更新。配布はコミット済ZIP、マージ禁止。
