# P02 小規模な全件Table再作成

場面：日次の販売レポート。数千～数万行程度の小さい教材から始める場合。

サンプル：`projects/minimal/models/mart_sales_daily.sql`

| 比較 | 内容 |
|---|---|
| メリット | 変更・物理削除を現在の入力から取り込みやすい。単純なSELECTで保守できる。 |
| デメリット | 更新のたびに対象全体を再計算する。大量・高頻度では負担が増える。 |

確認例：phase1は売上680、phase2は349。最終Tableはdbtで再作成するまで変わりません。

判断上の注意：少量ならIncrementalを導入する運用・調査コストの方が大きい場合があります。

事例は架空データに基づく教材です。実行手順は`docs/01-quickstart.md`、変更シナリオは`docs/02-change-scenarios.md`を参照してください。
