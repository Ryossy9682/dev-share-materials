# P09 BI向けの横持ちTable

場面：Looker Studioから複数のdimensionを一緒に使い、参照時のJoinを減らしたい。

サンプル：`projects/patterns/models/patterns/p09_wide_bi_table.sql`

| 比較 | 内容 |
|---|---|
| メリット | 利用者がSQLのJoinを書かずに使える。参照クエリの負荷を前処理へ移せる。 |
| デメリット | dimensionの重複保存と更新コスト。履歴・多対多・粒度を誤ると二重集計になる。 |

確認例：注文ID粒度で入金済み注文を公開します。日次粒度のmart_sales_dailyとは違うので件数の意味も確認します。

判断上の注意：500列を無条件に用意せず、BIの利用列を絞ります。Fact＋Dimensionの構成との比較は読取頻度と保守性で判断します。

事例は架空データに基づく教材です。実行手順は`docs/01-quickstart.md`、変更シナリオは`docs/02-change-scenarios.md`を参照してください。
