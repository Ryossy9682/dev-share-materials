# P11 個人・CI環境とstate/defer

場面：大きなDAGで、PRごとの検証を本番の未変更モデルと組み合わせたい。

サンプル：`reference-only/slim-ci.ps1.example`

| 比較 | 内容 |
|---|---|
| メリット | 全DAGを毎回作る負担を減らせる候補。個人・PRのdatasetを分けられる。 |
| デメリット | 本番artifactと参照権限が必要。deferで本番データを読む範囲を管理する必要がある。 |

確認例：state:modified+、--defer、--stateを読む参考例です。実際のCI接続・認証は同梱していません。

判断上の注意：今回のtargetへ出すmanifestで本番manifestを上書きしないでください。初回作成だけではIncrementalの2回目の挙動を検証できません。

事例は架空データに基づく教材です。実行手順は`docs/01-quickstart.md`、変更シナリオは`docs/02-change-scenarios.md`を参照してください。
