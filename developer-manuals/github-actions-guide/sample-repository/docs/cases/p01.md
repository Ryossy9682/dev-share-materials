# P01 View中心の構成

場面：小さい参照表や、常に最新状態を見たい低頻度レポート。

サンプル：`projects/patterns/models/patterns/p01_sales_view.sql`

| 比較 | 内容 |
|---|---|
| メリット | 結果Tableの定期再作成が不要。SQLの定義を共有しやすい。 |
| デメリット | 参照のたびに元データの計算が必要。高頻度BI・重い結合では費用と遅延が増えやすい。 |

確認例：phase2のseed後、Viewは再buildしなくても基礎データの変更を参照できます。SQL定義を変えた場合は再buildが必要です。

判断上の注意：Viewは計算結果のキャッシュではありません。Viewを増やすだけで費用が本数倍になるとも言えず、実際のSQLと処理バイトを確認します。

事例は架空データに基づく教材です。実行手順は`docs/01-quickstart.md`、変更シナリオは`docs/02-change-scenarios.md`を参照してください。
