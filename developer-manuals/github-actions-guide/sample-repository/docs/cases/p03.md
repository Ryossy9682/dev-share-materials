# P03 共通の重い結合を中間Tableに保存

場面：同じ注文・顧客結合を複数Martや複数BIから利用する。

サンプル：`projects/patterns/models/patterns/p03_orders_enriched_table.sql`

| 比較 | 内容 |
|---|---|
| メリット | 結合結果を再利用でき、下流のSQLを小さくできる。 |
| デメリット | 保存と更新の費用が追加。中間Tableが古いと下流も古くなる。 |

確認例：p03_sales_by_segmentとp09_wide_bi_tableが同じ中間結果を参照します。顧客102の変更後に再buildするとpremiumに集計されます。

判断上の注意：1対多Joinで注文が増殖すると集計が水増しされます。キーの一意性を先にテストします。

事例は架空データに基づく教材です。実行手順は`docs/01-quickstart.md`、変更シナリオは`docs/02-change-scenarios.md`を参照してください。
