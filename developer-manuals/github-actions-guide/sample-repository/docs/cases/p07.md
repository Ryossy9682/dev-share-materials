# P07 Snapshotによる顧客履歴（SCD Type 2）

場面：顧客セグメントが変更されても、以前の状態を残して分析したい。

サンプル：`projects/patterns/snapshots/customers.yml`

| 比較 | 内容 |
|---|---|
| メリット | dbt_valid_from/toで有効期間を保存できる。更新されたマスターの履歴を追える。 |
| デメリット | 継続実行と保存費用が必要。実行の間に起きた全変更は保証できない。 |

確認例：phase1の後にphase2を観測し、顧客102の旧segmentを閉じ、新segmentを追加。104の削除はhard_deletes=invalidateで旧行を閉じます。

判断上の注意：timestamp戦略はupdated_atが正しく進むことが前提。SnapshotはBigQueryのTable snapshotやバックアップとは別です。

事例は架空データに基づく教材です。実行手順は`docs/01-quickstart.md`、変更シナリオは`docs/02-change-scenarios.md`を参照してください。
