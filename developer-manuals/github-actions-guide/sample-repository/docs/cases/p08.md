# P08 Seed・Macro・Ephemeralの小さな共通処理

場面：少数の状態コード、日本語ラベル、割引計算、軽い1回利用のフィルター。

サンプル：`projects/patterns/models/patterns/p08_seed_lookup.sql`

| 比較 | 内容 |
|---|---|
| メリット | 小さい参照表をGitでレビューでき、式をMacroで共有できる。Ephemeralは中間物理Tableを作らない。 |
| デメリット | seed変更にはロードが必要。Macroを多用するとSQLが追いにくい。Ephemeralは単独参照・調査しにくい。 |

確認例：status_labels.csvとnet_amount.sql、int_paid_orders_ephemeral.sqlも読みます。注文件数が結合で増えないことを確認します。

判断上の注意：seedは大量データの取り込みや機密情報の保存先ではありません。EphemeralのSQLは各下流へ組み込まれ、計算再利用を保証しません。

事例は架空データに基づく教材です。実行手順は`docs/01-quickstart.md`、変更シナリオは`docs/02-change-scenarios.md`を参照してください。

出典： https://docs.getdbt.com/docs/build/seeds
