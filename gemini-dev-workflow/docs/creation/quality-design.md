# 品質改善の設計

共通ランタイムを.gemini/workflow/runtime/へ配置し、既存installerのコピー範囲に含める。各スキルは実行規約を読み、完了前にランタイム検査を呼ぶ。Markdownは人の正本、gate.jsonは検証用の構造化索引として元資料とハッシュで対応させる。

判定はファイル・対象SHA・終了コード・要件対応の整合性を扱う。承認者本人の真正性やレビューの意味的正しさまで保証しない。ホスト側のレビュー・CI権限と独立レビューを維持する。フックを唯一の必須ゲートにはしない。

gate.jsonを進行状態の唯一の正本とし、工程遷移・復旧・状況表示は共通ランタイムを使う。既存state.jsonは案件メタデータとして保持する。資料の追加は未分類として停止し、既存資料の変更は明示依存関係から再検証対象を算出する。Notion取得は既存のMCP手順で実施し、取得スナップショットを同じ依存検査に入力する。

変異テストは使い捨てコピーで明示された一意置換を適用する。実行するテストコマンドは導入先で選び、シェル文字列を自動評価しない。実行不能・タイムアウトを検出成功とみなさない。

更新履歴：独立レビューにより進行正本をgate.jsonへ統一。共有MDは工程別snapshotを保存し、後工程の正当な追記と基準資料の変更を区別する。実行証跡は根拠付き対象外ファイルを除いて照合する。
