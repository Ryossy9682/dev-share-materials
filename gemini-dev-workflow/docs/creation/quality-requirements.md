# 7項目の改善要件

承認：2026-10-14の利用者発言「1から7まですべて採用！」。対象は再利用ワークフローのv0.4.0。マージ・外部公開は実施しない。

| ID | 必要要件 | 受入条件 |
|---|---|---|
| DX-01 | 工程の機械判定 | 入力欠落・古い証跡・未承認・不正遷移で非0終了し、次工程へ進まない |
| DX-02 | 短いGeminiコマンド | setup/start/status/resume/check/impact/mutateを公式TOMLで提供し、導入先にも配置 |
| DX-03 | 要件とテストの対応 | 必須REQ/ACの設計・実装・ケース・実行結果の参照欠落を検出 |
| DX-04 | 中断復旧 | 工程完了時の保存と検証済み復元。壊れたZIP・パス逸脱・既存ファイル上書きを拒否 |
| DX-05 | 資料変更の影響限定 | 原本ハッシュ差分から依存する工程を推移的に特定。未登録資料は要分類 |
| DX-06 | テストの検出力 | 一時コピーで欠陥を注入。事前テスト失敗・生存変異・実行不能を合格にしない |
| DX-07 | ワークフロー回帰テスト | 停止・差し戻し・再開・資料変更・テスト不足を実行テストする |

Gemini自体の実機は未提供。ローカルPythonの挙動確認とGemini公式形式検査を分けて報告する。CI設定は配布し、ホスト側の必須チェック設定は導入時に行う。
