# 配布物自体の要件定義

版：1.0。根拠：2026-10-13の本セッション。ユーザーはローカルGitリポジトリ・ZIP納品を選択し、最後に「要件定義からリリース準備まで全部」「起きたらzipが出力されている」を依頼。既に確定した選択を実装範囲の承認として扱う。本番反映・リモート公開は依頼範囲外。

| ID | 必須要件・受入条件 | 対応 |
|---|---|---|
| REQ-01 | Gemini CLI/VS Code専用。公式仕様と2026-10-13時点の制約を明記 | README、compatibility、sources |
| REQ-02 | 共通手順のみ配布し具体的内容は導入先で考える。段階的読込 | GEMINI.md、14スキル |
| REQ-03 | 要件定義スキルは一問一答。既存枠を後日取込、人の承認 | requirementsスキル |
| REQ-04 | コード調査に基づく時間見積もりC/B/A。1=1時間 | investigate、estimate |
| REQ-05 | 詳細設計とテストケース設計、独立レビュー、差し戻し | design、review-design |
| REQ-06 | 要件に対応する実装と独立レビュー | implement、review-implementation |
| REQ-07 | UT単独の追加変更処理の行・分岐100%、結合ケース網羅 | tests、review-tests、coverage |
| REQ-08 | 同一問題3回未解決で停止、独立レビュー不可なら別セッション待ち | review、issues、handoff |
| REQ-09 | 主要ユースケース実行と証跡、未検証は停止 | verify、verification |
| REQ-10 | ブランチ/コミット/PRまで。直接・間接のマージ禁止 | contract、release |
| REQ-11 | 設計合格後自動進行、本番は毎回承認、事前条件で自動復旧 | stages、release |
| REQ-12 | 案件成果物・状態・引継ぎ・追跡をプロジェクトへ保存 | templates、workflow |
| REQ-13 | 導入時に既存ファイル保持、競合停止、再実行可能 | install.py、UT/結合 |
| REQ-14 | ローカルGit履歴とZIP、README導入手順、作成工程の証跡 | repository.bundle、docs/creation |

## 今回の完了境界

配布物の構成・導入ツールを検証しZIPを引き渡す。Gemini実機上の認証・ネイティブスキル起動・VS Code独立セッション・実アプリの本番反映はこの環境で実施できないため未検証として記録する。業務案件のリリースゲートを合格したとは扱わない。100%条件は配布物内の新規実装PythonツールのUTに適用する。Markdownはコードカバレッジの分母ではなく、要件照合・独立レビュー・シナリオ確認で評価する。

## 2026-10-14 更新（v0.2.0）

ユーザー追加指定に基づく変更。REQ-12の案件成果物保存先を/tmp/<repo-id>/<branch>/へ変更。REQ-15：要件定義冒頭でfeature.xxx名を決定し、取得時点で最新remote developのSHAから作成。REQ-16：各スキルの固定入力ファイルを自分で読み、本文・要約の引継ぎをしない。REQ-17：同じ工程のMDを加筆更新して最新本文と履歴を分離。REQ-18：PR向け整形MD・可搬な証拠・添付ZIPを作成。

この配布リポジトリはローカルのみでremote/developが存在しないため、実案件用のブランチ準備手順をこの配布更新に仮適用してdevelopを捏造しない。手順のGit動作は専用一時リポジトリで検証する。

## v0.3.0 追加要件

クローン先でGeminiを起動し、全資料ルートの構成・コード・テンプレート・概念資料を順次読む。可変領域を明示し、未読・未解決を残して初期設定を完成扱いにしない。初期設定と案件開発を分離する。
