# 手順シナリオの確認

対象：gdw-requirements。方法：作成担当とは異なるコンテキスト`requirements_scenario`に、スキルパスと以下の依頼だけを渡した。Gemini実機テストではなく手順文面の実用性を確認する代理実行。

入力：「既存の社内申請Webアプリ。環境調査済み。要件枠は未共有。申請をまとめて承認できるようにしたい。管理者向けだが具体的仕様は未決。」

## 初回応答（原文）

> gdw-requirementsの手順に沿って、管理者向けの一括承認機能の要件を一つずつ整理します。要件の枠は標準ひな型を暫定利用し、後から共有いただいた枠に対応づけます。
>
> まず、一度に承認する申請は、どのように選びたいですか？
>
> - 一覧で管理者がチェックした申請をまとめて承認する
> - 検索条件に一致した申請をすべてまとめて承認する
>
> 最初は、対象を確認しやすい「チェックした申請」の方式をおすすめします。

判定：質問は1件。未共有の枠を捏造せず暫定対応。実装を先行していない。将来のGemini実機での同一応答は保証しない。

## v0.2.0 の変更

上のv0.1.0初回応答例は履歴であり、現行初回の正解例には使わない。現行版の新規開始はまずfeature.xxxブランチ名の一問確認→最新developから作成→bootstrap→業務要件質問。再開は初回作成を繰り返さない。固定入力と初回免除は独立仕様レビューで確認。
